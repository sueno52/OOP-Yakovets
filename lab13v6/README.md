Лабораторна робота №13
======================

## Тема
Власні винятки та патерн Result.

## Мета
Навчитися створювати власні типи винятків для специфічних помилок, а також реалізовувати патерн Result для більш контрольованої обробки помилок без використання винятків у «нормальних» сценаріях невдачі.

## Хід роботи

1. **Створено консольний проєкт:** `dotnet new console -o lab13v6`
2. **Створено власний виняток `ImageProcessingException` (успадкований від `Exception`):**
   * властивості `ImageName` і `Operation`;
   * стандартні конструктори: `()`, `(message)`, `(message, innerException)`;
   * конструктори з назвою зображення й операцією (з `innerException` і без);
   * конструктор для серіалізації, позначений `[Obsolete]`, бо в .NET 8+ він застарів.
3. **Реалізовано узагальнений клас `Result<T>`:**
   * властивості `IsSuccess`, `Value`, `Error`;
   * приватний конструктор `Result(T value, bool isSuccess, string error)`;
   * фабричні методи `Success(T)`, `Failure(string)`, `Failure(Exception)`.
4. **Реалізовано сервіс `ImageProcessor`:**
   * **`byte[] ResizeImage(...)`** кидає `ImageProcessingException`, якщо дані пошкоджені (не PNG) або відсутні; в останньому випадку з `InnerException`.
   * **`Result<bool> ApplyFilter(...)`** повертає `Failure`, якщо фільтр невідомий; пошкоджені дані перетворює в `Failure(ex)`.
   * **`Result<byte[]> TryResizeImage(...)`** — «безпечна» версія `ResizeImage`, яка замість винятку повертає `Result`.
5. **Демонстрація в `Main`:** `try-catch` для власного винятку й перевірка `IsSuccess`/`Error` для `Result`.

## Фотозвіт

### Висновок

Для `ResizeImage` обрано виняток, бо пошкоджені дані — це неочікувана ситуація, після якої продовжувати обробку немає сенсу. Для `ApplyFilter` обрано `Result`, бо невідомий фільтр — звичайна помилка користувача, яку легко перевірити через `IsSuccess`, без `try-catch`.


## Контрольні запитання

1. **Навіщо створювати власні типи винятків? Які переваги це дає?**
   * Видно, що саме сталося: `ImageProcessingException` замість загального `Exception`. Можна ловити лише свій тип і передавати додаткові дані (`ImageName`, `Operation`).
2. **Які стандартні конструктори рекомендується реалізовувати для власних винятків?**
   * Порожній, з `message` і з `message` + `innerException`. Раніше ще для серіалізації, але в .NET 8+ він застарів.
3. **Поясніть патерн Result. У яких випадках його використання є більш доцільним, ніж викидання винятків?**
   * Метод повертає об'єкт, у якому або значення, або текст помилки. Доцільно для очікуваних невдач: невалідне введення, елемента не знайдено.
4. **Які сценарії краще обробляти через винятки, а які через патерн Result?**
   * Винятки — для неочікуваних збоїв (пошкоджені дані, немає файлу, мережа). `Result` — для звичайних, передбачуваних помилок користувача.
